The client typefaces embedded in the brand book.

Every family the app can name (see src/lib/book/fontCatalog.js) is published
under the SIL Open Font License 1.1. src/lib/book/brandFontData/ holds each one
instanced to a single weight, subset to printable ASCII, and stripped of
hinting and layout tables, so the brand book can show a client the real
letterforms of the typefaces chosen for them.

WHY THIS IS PERMITTED

The OFL grants permission to "use, study, copy, merge, embed, modify,
redistribute, and sell modified and unmodified copies of the Font Software",
and states that "the requirement for fonts to remain under this license does
not apply to any document created using the Font Software". The OFL FAQ
addresses this exact act directly:

  Q1.12  Can I embed the font in a document (like a PDF)?
         "Yes, either in full or a subset. The restrictions regarding font
         modification and redistribution do not apply, as the font is not
         intended for use outside the document."

  Q1.13  "Referencing or embedding an OFL font in any document does not change
         the license of the document itself."

This is a different act from the one src/lib/deliver/packagePlan.js refuses:
that guardrail is about putting redistributable font FILES in a client's
handover folder, which a commercial license almost never permits. Nothing in
brandFontData/ is ever written to a client package.

WHY THE SUBSETS ARE RENAMED

Five of these families carry a Reserved Font Name (Plex, Source, Lato, Libre
Baskerville, Playfair Display). SIL's guidance is that a subset cannot preserve
Functional Equivalence -- it fails the first criterion, "supports the same full
character inventory" -- and so is a Modified Version, which OFL clause 3 bars
from using the Reserved Font Name. So every subset here is renamed internally
to an opaque "CC Book Specimen <digest>" that contains no one's reserved words.
Copyright, trademark, designer, license and license-URL records are deliberately
left intact, per OFL FAQ Q1.14, and the brand book prints the true family name
and this license beside every specimen.

WHAT IS EMBEDDED IS NOT A USABLE FONT

One weight, 95 printable-ASCII glyphs, no hinting, no kerning, no ligatures, no
accents, no italic, and an internal name that does not claim to be the original.
It renders a specimen; it cannot stand in for the real typeface. That keeps this
an embedding -- which the FAQ defines as inclusion "in a way that makes
extraction (and redistribution) difficult or clearly discouraged" -- rather than
a way to get font files out of the product.
